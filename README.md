# telegram-bot

Мост «Bee»: пересылает сигналы из канала-источника (челлендж Arki) по таргетам:
TG #1 (русский перевод), TG #2 Heaven, TG #3 (английский, основной бот), аккаунты (Telethon),
Discord webhook Bee, selfbot-каналы Discord, webhook Rebel Angels; в конце — одна сводка админам.

**Два источника сразу** — когда трейдер начал новый челлендж, а в старом ещё доводит сделки:
`SOURCE_CHANNEL` (старый) и `SOURCE_CHANNEL_2` (новый). Посты обоих уходят во все таргеты;
webhook Bee у нового — только свой канал Discord (`DISCORD_WEBHOOK_URL_SOURCE_2`). Память
сделок для тега роли у каждого челленджа своя. В сводках админу — подпись челленджа
(`SOURCE_LABEL` / `SOURCE_LABEL_2`). Бот должен быть админом обоих каналов-источников.

Бота добавили админом в канал или группу (или убрали) — админам приходит название и ID чата.

## Как идёт пост
- **Текст** — те же правила, что у бота 5k-50k: `image_filter.py` — общий файл (там он
  `filters.py`), правится в обоих сразу. Стоп-лист Arki, продажа мест, призывы к подписчикам
  (лайки, follow, вступить, оплата, «turn on notifications»), бонусы и UID бирж, розыгрыши,
  спонсоры, пресейлы, речь о самой группе и набор в следующий челлендж, «reactions», ссылки и @username — в том числе замаскированные («t . me», «b1tunix»,
  «jоin» с русской «о», «𝐣𝐨𝐢𝐧»). Сигнал с рекламным хвостом не теряется: хвост вырезается,
  сигнал уходит, админу — «✂️ Вырезан рекламный хвост» (что было и что ушло).
- **Тег роли в Discord** (`pings.py`, общий файл с 5k-50k, переменная `DISCORD_PING`): в
  указанном selfbot-канале к важным действиям трейдера последней строкой добавляется тег роли —
  открыл позицию, долил по рынку, поставил/перенёс стоп или тейк, закрыл руками; убыток без
  стопа (значит, закрыл руками) — тоже. Убыток по стопу («Sl hit», «Lost», когда стоп был) — без
  тега. После тега 2 минуты — без тега: одна сделка двумя сообщениями подряд даёт один тег.
  В сводке у такого канала — 🔔, в /status — «🔔 тег роли на сделки».
- **Картинка** проверяется так же, как у бота 5k-50k (`image_filter.image_decision` — одно решение на оба бота; OCR RapidOCR,
  без внешних API). Режим — переменная `IMAGE_FILTER`:
  - `strict` (по умолчанию) — дальше уходят только карточки сделок/ордеров и балансы;
    реклама, профили копитрейдинга, бренды бирж, скрины Telegram/X/Discord, промокоды,
    QR, ссылки — блок; прочие картинки — админу на проверку;
  - `ads` — блокируется только реклама и чужие скрины, остальные картинки уходят;
  - `off` — картинки не проверяются.

  Не прошедший пост никуда не уходит: админам приходит картинка, причина и кнопки
  «✅ Всё равно переслать» (уйдёт во все таргеты) и «🗑 Убрать». Проверка занимает
  несколько секунд — Telegram-таргеты получают фото после неё.
- **Направления независимы**: у каждого (TG #1, Heaven, webhook Bee, каждый аккаунт,
  каждый selfbot-канал, Rebel Angels) своя очередь — посты в нём идут по порядку,
  а зависший аккаунт или упавший вебхук не задерживают остальных.
- **Discord selfbot и Rebel Angels**: первый канал — через `BRIDGE_DELAY_MIN..MAX` сек
  (10) от прихода поста, дальше паузы `SEND_DELAY_MIN..MAX` сек (5–7) между каналами.

## Переменные (новые и важные)
| переменная | по умолчанию | что это |
|---|---|---|
| `SOURCE_CHANNEL_2` | пусто | второй канал-источник (новый челлендж); пусто — источник один |
| `SOURCE_LABEL`, `SOURCE_LABEL_2` | пусто | подписи источников в сводках, например `250-1000` / `250-2500` |
| `DISCORD_WEBHOOK_URL_SOURCE_2` | пусто | webhook Bee для постов второго источника (свой канал Discord); пусто — в webhook Bee они не идут, в старый канал не попадают |
| `TARGET_CHAT_ID_3` | пусто | TG #3: канал/группа на английском, шлёт основной бот (он должен быть админом с правом публикации) |
| `TARGET_MESSAGE_THREAD_ID_3` | пусто | тема, если TG #3 — группа с темами |
| `TARGET_LABEL_3` | `TG #3` | как TG #3 называется в сводке и /checkchats |
| `IMAGE_FILTER` | `strict` | проверка картинок: `strict` / `ads` / `off` |
| `DISCORD_PING` | пусто | тег роли на сделки: `Название канала:id роли` через запятую (название — как в `DISCORD_CHANNELS`, или id канала), например `Minted:123456789012345678`; пусто — тегов нет |
| `BRIDGE_DELAY_MIN`, `BRIDGE_DELAY_MAX` | 10, 10 | сек от прихода поста до первого selfbot-канала |
| `SEND_DELAY_MIN`, `SEND_DELAY_MAX` | 5, 7 | сек между selfbot-каналами |
| `USER_SEND_TIMEOUT`, `USER_PHOTO_TIMEOUT` | 30, 90 | таймауты отправки от аккаунтов |
| `USER_START_DELAY` | 30 | сек до подключения аккаунтов после старта (защита сессий при деплое) |
| `OCR_THREADS` | 4 | потоков OCR |

## Сборка
Собирается по `Dockerfile` (python 3.11-slim + libgl1/libglib для OpenCV; модели OCR
распаковываются на сборке). Сессии аккаунтов: `python make_session.py` (локально, через
NekoBox; можно войти по QR — `qr` вместо номера) → `TG_USER_SESSION` / `TG_USER_SESSION_2`.
